# 内容整理策略

## 随手笔记

适合灵感、命令片段、短结论和待验证方案。保留原始语气，只做必要的结构整理：

1. 一句话标题。
2. 背景或触发点。
3. 核心想法。
4. 下一步或待验证项。

默认 `kind=note`、`visibility=private`。

## 技术文章

适合完整解决方案、故障复盘、架构设计和实践总结。优先使用：

1. 问题与背景。
2. 约束和目标。
3. 关键判断或根因。
4. 方案与实现。
5. 验证结果。
6. 权衡、边界与后续。

不要为了显得完整而虚构指标、故障现象或验证结果。将不确定内容明确标记为推断或待验证。

## 发布前检查

- 标题具体，不使用“关于某某的一些思考”之类空标题。
- 开头能说明读者为什么值得继续看。
- 代码、命令和配置使用代码块；不要包含真实凭据。
- 删除对话式铺垫、重复结论和只对当前会话有意义的指代。
- 公开内容必须再次检查公司信息、客户信息、内部域名、私人地址和身份信息。
- 标签使用现有标签且不超过 5 个；不为了分类完整而自动创建标签。
