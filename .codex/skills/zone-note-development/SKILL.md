# Zone 笔记开发

## 工作边界

将前端作为交互与状态层，将后端作为权限和数据真实性边界。

```text
zone-frontend-private  ->  zone-backend  ->  MongoDB
```

不要只通过隐藏 UI 保护数据。不要让请求参数决定资源所有者；从后端认证上下文获取当前用户。

## 开始前

1. 阅读仓库根目录 `AGENTS.md`。
2. 分别检查前后端仓库的分支与工作区状态。
3. 读取 [笔记架构](references/note-architecture.md)，定位本次任务涉及的所有入口。
4. 读取 [TDD 方案](references/tdd.md)，选择本次行为对应的测试层级。
5. 先写清请求字段、响应字段、默认值和授权矩阵，再改代码。

前后端是两个独立 Git 仓库。不要假设前端分支会包含后端变更；需要实现端到端能力时，分别
确认基线和分支。

## 实现顺序

### 0. 先写失败测试

将需求表达为用户可见行为或 API/权限契约，运行测试并确认它因缺少目标能力而失败。不要先写
实现再补一个必然通过的测试。

私密笔记至少先覆盖匿名用户、作者和其他登录用户的访问矩阵。前端先覆盖发送和回显
`visibility`，后端先覆盖读取范围与越权写入。

### 1. 固定领域契约

- 在后端 Mongoose model 与 Zod schema 中定义字段、枚举和默认值。
- 在前端 `lib/api/notes/types.ts` 同步请求与响应类型。
- 保持字段命名一致，不在 UI 层发明第二套映射。
- 为历史数据选择兼容读取或显式迁移，不假设 schema default 会回填旧文档。

### 2. 后端先收口权限

建立单一、可组合的可读范围，并复用于所有读取入口。私密笔记的基本不变量为：

```text
可读 = 明确公开 OR author 等于当前用户
```

将权限范围与搜索条件通过 `$and` 组合；搜索本身使用 `$or` 时，不要覆盖权限 `$or`。

同步检查：

- 单篇详情
- 分页列表、搜索与标签过滤
- 相邻笔记
- 标签分类聚合
- 浏览量更新
- 统计任务
- 更新与删除

私密资源对非作者返回与不存在资源相同的结果。更新和删除在数据库写条件中携带授权范围，
不要先查后改后遗漏竞态保护。

### 3. 接入前端

- 在 `NoteOptions`、`NoteInfo`、创建与更新参数中同步字段。
- 初始化编辑页时回显后端值；创建时提供明确默认值。
- 发布成功后只使用服务端响应更新 `useNotesStore`。
- 私密内容提供克制的状态标识，并移除没有意义的公开分享入口。
- 同步修改普通编辑页和拦截式 Modal 编辑页，或抽取共享逻辑后让两者复用。

不要基于前端角色推断私密笔记是否可读。让 API 响应决定内容是否存在。

### 4. 检查派生数据

判断新增字段是否会影响标签数量、最新笔记、站点统计、搜索总数、分页总数和前后篇导航。
公开页面的聚合不得暴露私密笔记的标题、数量、标签或更新时间。

涉及认证相关 GET 响应时，评估缓存隔离；优先避免把不同用户的结果放入共享缓存。

### 5. 验证

运行前端确定性检查：

```bash
bash .codex/skills/zone-note-development/scripts/verify.sh
```

需要验证生产构建时：

```bash
bash .codex/skills/zone-note-development/scripts/verify.sh --build
```

后端至少运行 `pnpm exec tsc --noEmit`；接入后端测试 runner 后，先运行最小相关测试再运行
完整测试。对权限功能补充访问矩阵验证，不能只验证作者成功路径。

## 完成条件

- 请求与响应类型在两端一致。
- 所有读写入口使用同一授权语义。
- 两套编辑/详情路由行为一致。
- 历史数据有明确兼容策略。
- 已验证匿名用户、作者和其他登录用户三类身份。
- 已评估 Changeset，并记录实际执行的检查。
